# Онлайн-сервер Базар блота

Ktor 3.3.0, Kotlin 2.2.21, JVM 21. Сервер использует тот же `game-core`, что и офлайн-клиент. Сессии и активные столы находятся только в памяти одного процесса; серверной БД и архива завершённых матчей нет.

## Разработка

Из корня репозитория с JDK 21, Node 24.19 и pnpm 11.25:

```sh
pnpm install
pnpm dev:online
```

Открыть http://localhost:5173 в четырёх независимых профилях браузера или на четырёх устройствах. Vite проксирует `/api` и WebSocket на Ktor :8080. Отдельные команды: `./gradlew :server:run` и `pnpm dev:web` после сборки движка.

Создатель выбирает название и таймер, получает шестизначный код и приглашает ещё троих. В лобби можно выбрать свободное место; NORTH/SOUTH и EAST/WEST — пары. Создатель запускает партию, когда подключены все четыре участника. После окончания раздачи любой участник может продолжить; сервер применяет переход только один раз.

Обычные вкладки одного браузерного профиля разделяют гостевой токен и считаются одним игроком. Для проверки четырёх мест нужны отдельные профили/устройства; Playwright использует четыре изолированных контекста.

## Production без контейнера

```sh
pnpm build
./gradlew :server:installDist
PUBLIC_ORIGIN=https://blot.example.com WEB_ROOT="$PWD/web/dist" server/build/install/server/bin/server
```

Сервер отдаёт также веб-клиент. Внешний reverse proxy должен завершать HTTPS и поддерживать WebSocket Upgrade на `/api/tables/{code}/ws`. Нужен **один экземпляр** сервера: несколько реплик без общего хранилища будут иметь разные столы и сессии.

## Docker и публичное размещение

```sh
docker build -t blot-online .
docker run --rm -p 8080:8080 -e PUBLIC_ORIGIN=https://blot.example.com blot-online
```

Образ содержит JVM-сервер и React/PWA, работает без БД и без дисковых томов. На локальном компьютере для проверки укажите `PUBLIC_ORIGIN=http://localhost:8080`. При доступе с телефона по LAN используйте соответствующий адрес как `PUBLIC_ORIGIN`.

Есть [Render Blueprint](../render.yaml): [открыть публикацию](https://render.com/deploy?repo=https://github.com/MTigra/armenian-belote-trainer-app). Развёртывание требует аккаунта владельца хостинга; сам файл не означает, что сервер уже опубликован. Render передаёт PORT и RENDER_EXTERNAL_URL, последний автоматически добавляется в допустимые origins. В бесплатном плане возможны сон/перезапуски — они уничтожают активные партии и гостевые сессии этой первой версии. Для стабильных матчей понадобится постоянно работающий процесс.

Сервис работает на [Render Free](https://armenian-blot.onrender.com/); HTTPS/WSS и полный матч четырёх гостей проверены. [Пошаговый запуск](../docs/deployment/render-free.md): Docker, Frankfurt, ветка `main`, единственный Free Web Service, ручные обновления между партиями. Сервис отдаёт также игру; на его собственной ссылке API настраивается автоматически. Перед входом клиент ждёт готовности сервера после сна до 90 секунд.

GitHub Pages запускает только статический клиент. Для игры по этой ссылке нужен отдельный доступный HTTPS/WSS сервер: задайте `VITE_API_URL=https://your-server` при сборке либо адрес в «Настройки подключения» на экране входа. Для приложения, отданного самим Ktor, адрес API совпадает с адресом сайта.

## Конфигурация

| Переменная | Значение |
| --- | --- |
| `PORT` | Порт HTTP, по умолчанию 8080; слушает 0.0.0.0 |
| `WEB_ROOT` | Папка собранного клиента; для Docker `/app/web` |
| `PUBLIC_ORIGINS` | Допустимые origins через запятую; без переменной разрешены локальные Vite/preview/Ktor и `https://mtigra.github.io` |
| `PUBLIC_ORIGIN` | Дополнительный публичный origin сервера, включая схему и порт, без пути |
| `RENDER_EXTERNAL_URL` | Автоматический origin сервиса Render |
| `JAVA_OPTS` | Параметры JVM; Docker задаёт heap 256 МБ и direct memory 64 МБ |

## Сессии, очередь и время

- Гость получает случайный ID, ник и 256-битный секретный токен. В HTTP он передаётся в Bearer-заголовке, в WebSocket — первым JSON-сообщением; токена нет в URL, публичных снимках или экспорте матча.
- На устройстве токен хранится отдельно от офлайн-сохранения. При перезапуске клиента `/api/me` возвращает активный стол, а WebSocket присылает свежую проекцию и возвращает управление. Очистка локальных данных может лишить игрока доступа к месту.
- Один гость занимает одно место. Несколько его вкладок допустимы; место считается подключённым, пока остаётся хотя бы одна связь.
- Все команды и таймеры упорядочены mutex. Команда содержит `requestId` и `expectedRevision`; повторный запрос не играет карту второй раз, устаревшее действие отклоняется. Клиент не применяет ход заранее и не повторяет его автоматически при переподключении.
- Сервер раздаёт карты через SecureRandom и проверяет действие за место, принадлежащее сессии. Во время матча отправляется только `PlayerView`: собственная рука, публичные события и количество чужих карт.
- Таймер задаётся для стола: null/30/60/120 секунд, по умолчанию 60. Он продолжает идти при отключении и в чате. Истечение времени выполняет допустимый пас/отказ от реконтры/карту, сохраняя управление у игрока.
- Через две минуты отсутствия место передаётся простому боту. При возвращении управление восстанавливается до следующего действия. Возврат не перезапускает таймер. В реконтре у партнёров независимые сроки ответа.
- Столы без подключённых игроков удаляются после шести часов без присутствия/команд; неактивные гостевые сессии без места — через 24 часа. Прекращение серверного процесса сразу удаляет все столы и сессии. Технические пределы первой версии: 256 столов и 10 000 гостевых сессий.

## Завершение и тренер

После завершения полная запись единожды передаётся текущим подключённым участникам. Затем стол и его состояние удаляются из серверного хранилища. Позднего скачивания нет: участник, пропустивший завершение, может не получить запись.

Клиент проверяет запись общим движком и сохраняет её в IndexedDB вместе с собственным местом, никами участников, таймером и собственным чатом. Офлайн-сохранение остаётся на месте. На случай ошибки хранилища доступны повторное сохранение и скачивание записи.

Онлайн-игра не ждёт тренера. HTTP `/api/trainer` пока возвращает 503 `TRAINER_UNAVAILABLE`; внешний AI-провайдер будет подключён отдельно. Чат показывает, что партия продолжается; вопрос и будущий ответ связаны с состоянием на момент отправки, старые сообщения помечаются как относящиеся к прошлому моменту.
