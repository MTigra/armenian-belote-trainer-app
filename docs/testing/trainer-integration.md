# Проверки AI-тренера

15 октября 2026. Реализованы P05/P06/P09 в рабочем дереве, без публикации.

## Проверенный объём

- Сервер: строгие DTO, три source, серверный онлайн-снимок с правами/revision,
  replay завершённого архива, приватная проекция, оба профиля 0.1/0.2.
- Пересчёт offline options через код движка, кандидаты карт, торговли,
  контры вне очереди, реконтры и ручных объявлений.
- Gemini REST с системным промптом, JSON Schema, проверкой finishReason,
  формата, ruleRefs, ID действий и применимости на копии исходного состояния.
- Ошибки, тайм-аут, ограниченный повтор, дедупликация и кеш без хранения секретов.
- Клиентский чат, совет/альтернативы/предположения, исходный момент,
  обе перспективы review, сохранение в IndexedDB, exportVersion 2 и чтение v1.
- Ресурсы prompt/schema/rules включаются в серверную сборку. Docker context
  включает эти файлы; production не читает docs из файловой системы.

## Автоматические проверки

Серверные TrainerTest и GeminiTrainerTest используют mock провайдера/HTTP:
проверяют приватность, неверные ID/дубли, допустимые действия двух профилей,
завершённость review, границы раздач, историю без будущего/all_hands, повторы,
конфликты ID, тайм-аут, bearer и независимость таймера от ожидающего AI.
Отдельный случай берёт реальную вторую раздачу до третьей сыгранной карты и
подтверждает равенство состояния с replay. Неверный формат и превышение тела
проверяются через настоящий Ktor route. В обычных тестах внешней сети нет.

Клиентские тесты проверяют полный ответ, несовпадение requestId/момента,
отправку online-ссылки без руки, фильтрацию истории и миграцию экспорта.
Браузерные trainer.spec.ts проверяют успешный ответ, повтор с тем же ID,
сохранение после reload и разделение двух перспектив review. online.spec.ts
задерживает ответ, продолжает настоящую онлайн-игру и затем проверяет отметку
«прошлый момент», сохранение двух сообщений и неизменность WebSocket.

При первом полном прогоне исправлены два теста: архив теперь содержит вопрос
и успешный ответ вместо одного вопроса при заглушке; тест касания выбирает
реально открытую область карты после поворота, поскольку соседняя перекрывающаяся
карта иногда закрывала прежнюю фиксированную координату. Продуктовая раскладка
карт в этой задаче не менялась.

## Реальный запрос Gemini

Проверен путь JS PlayerView → HTTP Ktor → Gemini gemini-3.8-flash → валидатор → HTTP.
Состояние получено из реального движка: вторая раздача, уже сыграны две карты,
actionIndex=45, SOUTH должен ответить о показе комбинаций перед своей картой.
Модель получила только PlayerView и публичную историю, без GameState/MatchRecord.

- Первая попытка получила временный 503; сервер сделал один ограниченный повтор
  и вернул клиенту TRAINER_UNAVAILABLE, retryable=true.
- Следующий отдельный запрос вернул HTTP 200 за 9,35 секунды.
- suggestion: declare для SOUTH; альтернатива: decline-declarations.
- Объяснение относилось к собственному трефовому терцу 10–В–Д.
- Сервер подтвердил формат и допустимость обеих команд. Стратегия отмечена
  not_evaluated. Состояние игры не менялось.

Ключ использовался только в окружении временного локального процесса;
в исходниках, примерах, тестах и логе ответа его нет. Реальный тест не запускается
в CI. Этот запрос не подтверждает суточную бесплатную квоту, стоимость,
стабильную задержку или стратегическое качество на корпусе из 20 ситуаций.
P04 в этой части остаётся открытой.
