# Размещение на Render Free

Пользователь выбрал Render Free 14 октября 2026 года. Один Docker-сервис отдаёт Ktor API, WebSocket и собранный React/PWA. База данных и другие платные сервисы не нужны. Публичная публикация пока ожидает создания сервиса в аккаунте владельца.

## Создание сервиса

1. Открыть [готовый Blueprint в Render](https://render.com/deploy?repo=https://github.com/MTigra/armenian-belote-trainer-app) и войти в свой аккаунт. При необходимости разрешить Render доступ к этому GitHub-репозиторию.
2. Выбрать создание Blueprint из ветки `main`. Конфигурация находится в корневом [render.yaml](../../render.yaml).
3. Проверить, что создаётся единственный **Web Service**, runtime **Docker**, plan **Free**, region **Frankfurt**. Платные БД, диски и другие сервисы не добавлять.
4. Применить Blueprint кнопкой Deploy/Create/Apply в зависимости от экрана Render и дождаться успешного первого deploy.
5. Скопировать фактическую ссылку сервиса вида `https://….onrender.com` из Dashboard. Имя может получить суффикс; адрес заранее не предполагаем.

Если ссылка Blueprint не открывает нужный мастер: Dashboard → New → Blueprint, репозиторий `MTigra/armenian-belote-trainer-app`, ветка `main`, файл `render.yaml`. Альтернативно можно создать Web Service вручную с теми же параметрами, корнем репозитория и Dockerfile `./Dockerfile`.

## Проверка после публикации

- Открыть `https://<фактический-адрес>/api/health`: ожидается JSON `{"status":"ok","protocolVersion":"1"}`.
- Открыть корневую ссылку сервиса на телефоне: должен загрузиться Базар блот. Адрес API совпадает с адресом страницы, поэтому настройки подключения менять не требуется.
- Создать стол, пригласить ещё трёх гостей на этот же адрес и подключиться по коду. Разные вкладки одного профиля считаются одним гостем; нужны разные устройства/профили.
- Проверить торговлю, ходы, возврат после reload, таймер и локальную историю. Полную проверку публичного HTTP/WSS и четырёх клиентов выполняем после получения действующего адреса.

Ktor автоматически добавляет `RENDER_EXTERNAL_URL` в разрешённые origins. Также разрешён клиент GitHub Pages. Чтобы прежняя ссылка GitHub Pages использовала сервер по умолчанию, после появления реального URL пересобираем её с `VITE_API_URL=https://<фактический-адрес>`. До этого можно указать адрес в «Настройки подключения».

История и гостевой доступ привязаны к origin браузера. Записи, сохранённые на GitHub Pages, остаются там; для переноса на Render можно использовать экспорт/импорт истории.

## Сон, память и обновления

- Free предоставляет 512 МБ памяти; Docker задаёт JVM heap 256 МБ и direct memory 64 МБ. CI проверяет запуск образа с ограничением памяти 512 МБ. Это проверка старта/API/клиента, а не нагрузочный тест большого числа столов.
- После 15 минут без входящего трафика Render останавливает сервис. Первое подключение после перерыва может занимать около минуты. Клиент ждёт готовности `/api/health` до 90 секунд и только затем отправляет создание гостя/стола или подключение. Повторяются только безопасные GET; POST-команды не повторяются автоматически.
- Переход из подключения в офлайн-тренировку отменяет ожидание. Просроченный после серверного перезапуска гостевой токен заменяется перед новым подключением.
- Сон, redeploy и любой перезапуск удаляют активные партии и гостевые сессии: они находятся в памяти. Завершённые записи на устройствах сохраняются. Render вправе перезапускать Free-сервис; [условия тарифа](https://render.com/docs/free).
- В Blueprint отключён автоматический deploy при push (`autoDeployTrigger: "off"`). После успешного CI обновлять вручную: Dashboard → сервис → Manual Deploy → Deploy latest commit. Делать это между партиями. При первом создании Render всё равно запускает initial deploy.

## Текущий статус

Конфигурация и поддержка холодного запуска подготовлены. Доступа к аккаунту Render в среде Codex нет; сервис здесь не создан. Публичный URL, успешный deploy и проверка игры через Интернет пока ожидаются. Аккаунт, пароль и API-ключ не нужно отправлять в чат: достаточно создать сервис через Blueprint и прислать публичную ссылку.
