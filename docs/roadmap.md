# Задачи и порядок разработки

Обновлено: 14 октября 2026 года.

Здесь ведём текущие статусы, очередь работ и зависимости. Принятые требования находятся в [технических решениях](technical-decisions.md), правила — в [профиле игры](rules/profile-v1.md), результаты проверок — в [docs/testing](testing/).

Проект без согласованных сроков: календарные даты завершения пока не назначаем. Очередь следующих этапов — рабочее предложение, которое можно менять по результатам проверки игры и пожеланиям пользователя.

## Сейчас

Работает [веб-версия](https://mtigra.github.io/armenian-belote-trainer-app/) с офлайн-партиями, сохранением и просмотром истории. Исходники опубликованы в `main`, сайт — из `gh-pages`. Онлайн доступен через [Render Free](https://armenian-blot.onrender.com/) и прежний GitHub Pages с автоматически настроенным API. Оба адреса проверены полноценными матчами четырёх браузерных гостей через HTTPS/WSS. Реальные ответы тренера ещё не подключены.

Реализованы P03, P07, P08 и P10: Ktor, приватные онлайн-столы, гостевые сессии/таймеры/возврат и локальная история. Они проверены четырьмя браузерными клиентами. P01 завершена: чистый GitHub Actions прошёл, включая сервер, браузерные сценарии и Docker. Для P09 подготовлены продолжающаяся партия и привязка чата к снимку; внешний AI ещё не подключён. **P11 завершена:** пользователь создал Render Free; проверены HTTPS/WSS, два публичных браузерных матча, CORS и default API GitHub Pages с миграцией старых настроек. [Инструкция публикации](deployment/render-free.md). P02 продолжается: полный прогон Android/iOS ещё не завершён.

Исправлены P14–P19 после проверки с друзьями и P20 — собственное имя гостя. [Проверки исправлений](testing/friends-fixes.md): 80 JVM + 80 JS, 17 серверных, 27 клиентских тестов и 8 браузерных сценариев. Код (`20a1889`) и [чистый CI](https://github.com/MTigra/armenian-belote-trainer-app/actions/runs/38617620519) полностью проверены, включая Docker. Render обновился до протокола 2; GitHub Pages опубликован (`3752657`), все 50 файлов совпали с проверенной сборкой. На обоих адресах прошли публичные HTTPS/WSS-матчи четырёх гостей и отдельные офлайн-сценарии.

## Известные вопросы

- **Правило R21:** приоритет рамок в бое остаётся предварительным в профиле `armenian-training-0.1`. Используем предоставленный вариант; изменение требует отдельного решения и обновления тестов/версии правил.
- **P15:** согласованы отказ и таймер без бонуса, автоматические объявления ботов и блот-реблот. Новые партии — профиль 0.2, прежние архивы/сохранения — 0.1; [дополнение](rules/profile-v2.md).
- **Онлайн-переподключение:** таймер продолжает идти в период ожидания, выполняя допустимое действие при истечении. Через две минуты управление получает бот; возврат не сбрасывает срок текущего хода.
- **Render Free:** первый вход после сна может занять около минуты; сон, redeploy и перезапуск удаляют активные партии. Завершённые локальные записи сохраняются. Публичные проверки выполнены в мобильном Chromium, физические устройства остаются в P02.
- **История онлайн:** участнику, пропустившему завершение матча, получение записи не гарантируется. Постоянный архив на сервере не запланирован.
- **Публикация сайта:** `pnpm build:pages` задаёт Render API, затем сайт обновляется отдельным скриптом; push исходников в `main` сам по себе не пересобирает GitHub Pages и не делает redeploy Render. Автоматизацию публикации можно добавить отдельной задачей.

## Как поддерживаем файл

- Перед началом работы отмечаем конкретную задачу как **в работе**; при препятствии — **заблокировано** с причиной.
- После завершения переносим результат в «Готово» и добавляем подтверждение: проверку, документ или коммит. Невыполненные части оставляем отдельными задачами.
- Новые проблемы записываем отдельными пунктами с устойчивым ID и зависимостями. ID существующих задач не меняем.
- При изменении приоритетов обновляем очередь и дату документа. Сроки добавляем только по договорённости.
- Технические решения храним в отдельном документе, а этот файл используем как актуальный список работ.
