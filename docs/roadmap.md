# Задачи и порядок разработки

Обновлено: 14 октября 2026 года.

Здесь ведём текущие статусы, очередь работ и зависимости. Принятые требования находятся в [технических решениях](technical-decisions.md), правила — в [профиле игры](rules/profile-v1.md), результаты проверок — в [docs/testing](testing/).

Проект без согласованных сроков: календарные даты завершения пока не назначаем. Очередь следующих этапов — рабочее предложение, которое можно менять по результатам проверки игры и пожеланиям пользователя.

## Сейчас

Работает [веб-версия](https://mtigra.github.io/armenian-belote-trainer-app/) с офлайн-партиями, сохранением и просмотром истории. Исходники опубликованы в `main`, сайт — из `gh-pages`. Реальные ответы тренера и онлайн-столы ещё не реализованы.

Реализованы P03, P07, P08 и P10: Ktor, приватные онлайн-столы, гостевые сессии/таймеры/возврат и локальная история. Они проверены четырьмя браузерными клиентами. P01 исправлена локально и ожидает подтверждения GitHub Actions. Для P09 подготовлены продолжающаяся партия и привязка чата к снимку; внешний AI ещё не подключён. **P11 отложена по решению пользователя:** публичное размещение выберем позже. P02 продолжается: полный прогон Android/iOS ещё не завершён.

## Известные вопросы

- **P01:** [последний проверенный CI-запуск](https://github.com/MTigra/armenian-belote-trainer-app/actions/runs/38561858339) завершился на `kotlinStorePackageLock` с ошибкой `Lock file was changed`. Причина найдена: старые версии unspecified в Kotlin JS lock-файле. Четыре поля исправлены, чистая локальная сборка проходит; удалённый прогон исправления ещё ожидается.
- **Правило R21:** приоритет рамок в бое остаётся предварительным в профиле `armenian-training-0.1`. Используем предоставленный вариант; изменение требует отдельного решения и обновления тестов/версии правил.
- **Онлайн-переподключение:** таймер продолжает идти в период ожидания, выполняя допустимое действие при истечении. Через две минуты управление получает бот; возврат не сбрасывает срок текущего хода.
- **История онлайн:** участнику, пропустившему завершение матча, получение записи не гарантируется. Постоянный архив на сервере не запланирован.
- **Публикация сайта:** сейчас обновляется отдельным скриптом; push исходников в `main` сам по себе не пересобирает сайт. Автоматизацию публикации можно добавить отдельной задачей.

## Как поддерживаем файл

- Перед началом работы отмечаем конкретную задачу как **в работе**; при препятствии — **заблокировано** с причиной.
- После завершения переносим результат в «Готово» и добавляем подтверждение: проверку, документ или коммит. Невыполненные части оставляем отдельными задачами.
- Новые проблемы записываем отдельными пунктами с устойчивым ID и зависимостями. ID существующих задач не меняем.
- При изменении приоритетов обновляем очередь и дату документа. Сроки добавляем только по договорённости.
- Технические решения храним в отдельном документе, а этот файл используем как актуальный список работ.
