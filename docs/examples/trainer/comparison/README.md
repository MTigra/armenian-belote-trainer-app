# Запрос для сравнения моделей на точной руке пользователя

Пики В–9–7, бубны 10–Т, червы К, трефы В–7. Открытие торговли,
SOUTH, дилер EAST, исходный счёт 0:0 (прочие параметры тестового состояния).

- user-hand-request.json — полное тело запроса с опубликованным промптом,
  включая system, user, schema и параметры Groq. Без ключа, он шёл заголовком.
- user-hand-request.http — тот же запрос с URL/заголовками; ключ заменён маркером.
- user-hand-readable.txt — весь system, user JSON и схема с отступами для
  чтения/переноса в чат другой модели. Никакие части контекста не сокращены.
- user-hand-response.json — фактический ответ Ktor из нового контрольного вызова
  815cd861-3345-4e3a-8bb5-0c70e71a05f1: 9 пик, HTTP 200 за 8,35 секунды.

JSON запрос сформирован тем же production requestBody, что отправляет Ktor;
перед вызовом сохранён отдельно. Строки messages полностью совпадают; отступы
внешнего JSON не влияют на сообщения. Ключей, кода доступа и скрытых рук нет.
Ответ не исправлен: в нём есть ошибка «третий треф», неподтверждённая безопасность
заявки и некорректное объяснение альтернативы 8. В предыдущем вызове тот же
провайдер выбирал 8 пик, 9 — альтернативой. Один правильный ID не доказывает
качество стратегии или аргументации; validation.strategy=not_evaluated.
