# Техническое обсуждение

Статус: технические решения обсуждены, правила предоставлены. Общий модуль, React-интерфейс, Ktor и приватные онлайн-столы реализованы; сервер и клиент опубликованы на Render Free, публичный матч четырёх гостей проверен. Актуальная очередь работ, зависимости и подтверждения завершения — в [roadmap.md](roadmap.md).

## Принято пользователем

- Основная платформа — веб. Android и iOS планируются через Capacitor или аналогичную обёртку; выбор конкретной обёртки ещё не окончательный.
- Первый выпуск: офлайн-игра с ботами и приватные онлайн-столы по коду. Публичный подбор соперников отложен.
- Без интернета работают боты и просмотр скачанных матчей; AI-чат требует подключения.
- Тренер доступен во всех режимах, включая онлайн.
- Во время матча тренер получает только информацию игрока: собственные карты, публичные действия, торговлю, историю и вопрос. Скрытые карты остальных не передаются.
- После матча доступны разбор с позиции игрока и разбор с раскрытыми картами.
- Тренер использует внешний API языковой модели через сервер. Конкретная модель и расходы будут оценены позже; отдельный анализатор силы ходов не входит в первую версию.
- Ответ тренера структурированный: предлагаемое действие, объяснение и альтернативы. Проверяем формат ответа и допустимость предлагаемого действия; стратегическую правильность объяснения автоматически не оцениваем.
- Клиент — React + TypeScript + Vite.
- Сервер — Kotlin + Ktor.
- Общие правила — модуль Kotlin Multiplatform для JVM и JavaScript.
- Все участники первой версии — гости. Аккаунты и синхронизация между устройствами отложены.
- Локальные матчи хранятся в IndexedDB; небольшие настройки — в localStorage. Будут импорт и экспорт матчей.
- Во время разговора с тренером офлайн-боты приостанавливаются; онлайн-партия продолжается.
- Вопрос и ответ тренера привязаны к состоянию игры на момент вопроса. Если текущая партия изменилась, ответ помечается как относящийся к прошлому моменту и не применяется как актуальное действие без новой проверки.
- Онлайн: сервер — источник истины, раздаёт карты, проверяет действия и выдаёт только информацию конкретного игрока. WebSocket для игровых событий, HTTP для обычных запросов и тренера.
- Гость получает автоматически сгенерированный ник и секретный токен сессии. После перезапуска клиента восстанавливается его место в существующей онлайн-партии. После очистки локальных данных доступ к месту может потеряться.
- При отключении игрока сохраняем место. Принято предложенное ожидание до двух минут, затем управление передаётся простому боту; возвращение игрока восстанавливает управление перед следующим собственным действием. Таймер хода продолжает идти во время ожидания; его истечение выполняет допустимое действие независимо от двухминутного срока передачи управления боту.
- Незавершённые онлайн-матчи после перезапуска сервера не восстанавливаются.
- Ограничение времени на действие настраивается для каждого стола. Значения и автоматическое действие описаны ниже; таймер реализован в Ktor.
- После завершения сохраняются исходная раздача, торговля, все ходы и собственные диалоги с тренером. Полная раздача доступна для просмотра только после завершения матча.
- В первой версии серверной БД нет: активные столы и сессии хранятся в памяти Ktor. Сервер не хранит историю завершённых матчей и не предоставляет архив для позднего скачивания. При завершении полная запись передаётся подключённым участникам для локального сохранения. Доступность записи участнику, пропустившему завершение, отдельно не гарантируется.
- Таймер стола: без ограничения, 30, 60 или 120 секунд; по умолчанию 60. Применяется к действиям в торговле и розыгрыше; время отсчитывает сервер.
- По истечении времени выполняется одно допустимое действие. В торговле — пас, если правила допускают его. Управление остаётся у игрока. Таймер действует и при потере связи.
- Незавершённая офлайн-партия сохраняется после каждого действия. В главном меню должно появляться действие «Продолжить партию» при наличии сохранения. Кнопка продолжения и подтверждение замены реализованы в React-интерфейсе.
- Для первого запуска тренер требует отдельного кода доступа. Код проверяется сервером; API-ключ модели не передаётся клиенту. Детали выдачи кодов и лимитов ещё не выбраны.
- Веб-клиент опубликован на GitHub Pages из ветки `gh-pages`. Ktor размещён на https://armenian-blot.onrender.com; GitHub Pages использует этот API.
- Одно активное сохранение офлайн-тренировки. Перед новой тренировкой предложить продолжить старую или подтвердить её замену. Онлайн-игры не перезаписывают офлайн-сохранение.
- Экспорт/импорт матчей — JSON с версией формата, версией правил, исходной раздачей, настройками стола, последовательностью действий и собственным чатом. При импорте проверяется структура и совместимость версии.
- Код доступа к тренеру — один общий четырёхзначный код. Хранится в конфигурации сервера; смена возможна без управления отдельными приглашениями. По явному решению пользователя ограничения попыток ввода кода нет. Лимиты запросов к модели не согласованы.
- Один репозиторий для клиента, Ktor-сервера и общего модуля правил. Для сборки используются pnpm и Gradle Kotlin DSL; общий модуль Kotlin Multiplatform собирается для JVM и JavaScript.
- Приняты тесты общего модуля на JVM и JavaScript с одинаковыми сценариями, тесты Ktor для действий/видимости/переподключения/таймера, Vitest для клиентской логики, Playwright для основных пользовательских сценариев. CI выполняет сборку, проверки типов и тесты. Внешняя модель в обычных тестах заменяется фиксированными ответами; качество реальных советов оценивается отдельно.
- Недоступность, ошибки и задержки тренера не препятствуют игре. Клиент чата имеет собственные состояния ожидания/ошибки и повторного запроса; игровой цикл не ждёт ответа модели. Ошибки AI-запроса не разрывают игровой WebSocket и не изменяют партию.
- Первые офлайн-боты лишь соблюдают правила и выбирают разрешённые действия. Тактические эвристики и развитие силы игры отложены.
- Проект поддерживает пользователь: бэкенд-разработчик, знаком с Java/Kotlin и открыт к TypeScript.
- Pet-проект, жёсткого срока нет. Бюджет пока не определён; требуется понять варианты внешнего API и локального запуска модели.

## Уточнение последнего раунда

- Предложение хранить завершённые записи на сервере 24 часа отклонено: история исключительно локальная.
- Ограничение попыток ввода кода тренера отклонено.
- Независимость игрового процесса от доступности тренера подтверждена.
- pnpm и Gradle Kotlin DSL объяснены и используются в реализации.

## Отложено

- Аккаунты и синхронизация истории между устройствами.
- Тактический интеллект ботов.
- Публичный подбор игроков.
- Выбор конкретной модели и оценка бюджета на примерах.

## Ещё не решено

Остаются выбор модели, конфигурация секретов тренера и наблюдаемость. Render Free выбран и размещён; ограничения сна/перезапуска приняты для pet-проекта. Взаимодействие таймера с ожиданием отключившегося игрока определено и реализовано: таймер продолжает идти, через две минуты управляет бот. Формат локальной записи, replay, тесты и инструменты сборки уже реализованы; расхождение Kotlin JS lock-файла исправлено и подтверждено [чистым CI](https://github.com/MTigra/armenian-belote-trainer-app/actions/runs/38584501250) (P01 завершена). Правила получены и сохранены ниже.

## Переданная спецификация правил

Получены и сохранены без изменений `rules/profile-v1.md`, `rules/armenian-blot.md`, `rules/sources.md`. Рабочий профиль — `armenian-training-0.1`: цель 301, 32 карты, восемь карт каждому, козырные контракты и бой, заявки от 8 с шагом от 1, четыре последовательных паса, контра/реконтра, автоматические объявления и расчёт результатов. R21 остаётся предварительным в существующем варианте.

Старые поручения и сведения о прежней реализации в файлах не заменяют текущих пользовательских решений. На момент получения вложений общий модуль и PWA не были реализованы. Сейчас общий модуль правил реализован в `game-core`; React/PWA теперь подключены к движку; Ktor-интеграция выполнена, сервер проверен четырьмя браузерными клиентами. Различия макета и профиля перечислены в `rules/README.md`.

## Реализованный этап: общий модуль

Kotlin 2.2.21, Gradle Wrapper 8.14.3, JDK 21, kotlinx.serialization 1.9.0. JVM и JavaScript используют один commonMain и один commonTest. Есть публичная проекция игрока без скрытых рук, JSON-снимки и версионированные записи, детерминированный replay, простое автоматическое действие для ботов/таймера и строковый JSON API для JavaScript. 68 сценарных тестов локально прошли на обеих платформах. Сетевая авторизация, таймер, IndexedDB, AI и интерфейс не входят в этот этап. CI выполняет всю цепочку проверок; прежнее расхождение версий Kotlin JS lock-файла исправлено.

## Реализованный этап: React-интеграция

Рабочее приложение находится в `web/`: React 19.2, TypeScript 5.9, Vite 7.1, pnpm 11.25. Общий ES-модуль подключается через typed JSON-адаптер. Торговля и розыгрыш используют реальный `PlayerView`; несуществующие/недопустимые карты неактивны. Все действия пользователя и ботов принимает Kotlin-движок. Одна тренировка сохраняется в IndexedDB; завершение атомарно переносит запись в историю и очищает активный слот. Есть продолжение, подтверждение замены, просмотр событий, раскрытая раскладка после матча и версионированный JSON-обмен.

Боты ждут, пока открыты меню/чат. PWA собранного приложения кеширует ресурсы и запускается без сети после первого посещения. Код тренера хранится только в памяти страницы и не включается в историю/экспорт. Чат использует отдельный HTTP-клиент; без сервера показывает ошибку, не генерирует фиктивных ответов и не изменяет партию. Подключение к людям использует Ktor; для публичного сайта нужен отдельно размещённый сервер. Предыдущий статический макет сохранён в `docs/design-prototype/`.

Локально пройдены 10 Vitest-тестов и 3 браузерных сценария; подробности в `testing/react-integration.md`. Node 24, JDK 21 и Gradle Wrapper используются для сборки. Статический клиент опубликован на GitHub Pages и проверен по публичной ссылке. Публичное размещение Ktor и реальные ответы AI остаются следующими этапами.

## Реализованный этап: онлайн

Ktor 3.3.0, JVM 21; активные столы и гостевые сессии в памяти. Приватные столы по шестизначному коду, выбор места до старта, четыре подключённых гостя и старт создателем. HTTP и WebSocket используют типизированные DTO, сервер связывает действия с гостевым местом, упорядочивает их и проверяет общим движком. requestId и revision исключают повторное применение и устаревшие ходы. Случайная раздача использует SecureRandom.

При потере связи работают таймер и двухминутное ожидание; затем управляет бот. Возврат восстанавливает место без сброса таймера. Онлайн продолжается в меню и чате; сообщения привязаны к моменту отправки. Полная запись передаётся подключённым участникам только при завершении и удаляется с сервера. Клиент сохраняет собственное место и диалог отдельно от офлайн-тренировки.

Локально прошли 15 серверных, 17 Vitest и 5 браузерных сценариев. Из чистых build-выходов прошли JVM/JS-критерии; исправлен прежний lock-файл с устаревшими версиями. Подготовлены Docker и Render Blueprint. [GitHub Actions](https://github.com/MTigra/armenian-belote-trainer-app/actions/runs/38584501250) подтвердил все проверки, сборку и запуск Docker с API и клиентом. Пользователь создал Render Free; сервер доступен по HTTPS/WSS и проверен настоящим браузерным матчем четырёх гостей. AI по-прежнему недоступен. Подробности — [проверки](testing/online-integration.md) и [сервер](../server/README.md).

## Выбранное размещение: Render Free

Один Docker Web Service во Frankfurt, ветка main, plan Free. Ktor отдаёт также React/PWA; API и игра имеют один origin. Фактический URL — https://armenian-blot.onrender.com. `pnpm build:pages` задаёт этот API для GitHub Pages. Автоматический deploy отключён, чтобы каждый push не прерывал партии. Сон или перезапуск по-прежнему удаляет активные столы; клиент ждёт готовности сервера до 90 секунд, отменяет ожидание при уходе с экрана подключения и обновляет просроченный гостевой доступ. Инструкции и статус — [Render Free](deployment/render-free.md).

## Исправления после игры с друзьями (14 октября 2026)

Профиль 0.2 вводит добровольные обычные объявления: решение перед первой
картой, разрешённое раскрытие во второй взятке; отказ и таймер отменяют бонус,
бот соглашается, блот-реблот автоматический. Старые записи/сохранения 0.1
продолжаются без миграции правил. Движок считает текущие карточные очки
раздачи отдельно от малых очков партии. Протокол сервера 2 предотвращает
подключение старого клиента к новым действиям; новый клиент принимает 1 и 2.

Карты — локальные SVG-cards с номиналами в контурах, одна колода для всех
экранов; лицензии/источник в `assets/card-source` и `web/public/cards`.
Анимации CSS используют transform/opacity, реагируют на новые игровые карты
и взятки, не на присутствие/rename; reduced-motion исключает сбор взятки.
Имя гостя сохраняется локально, POST `/api/me` меняет имя без смены токена,
места, игровой revision или таймера; обновление рассылается игрокам.
