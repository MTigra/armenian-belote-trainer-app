# React-интерфейс Базар блота

React 19, TypeScript, Vite. Офлайн использует скомпилированный Kotlin Multiplatform-модуль через `src/lib/engine.ts`, онлайн — авторитетный Ktor через `src/lib/useOnlineGame.ts`. Игровая логика не дублируется в TypeScript. Согласованный стол и оформление сохранены.

## Запуск из корня репозитория

Требуются JDK 21, Node 24, pnpm 11.25.0.

```sh
pnpm install
pnpm dev
```

`pnpm dev` сначала собирает JavaScript-пакет общего движка через Gradle Wrapper, затем запускает Vite на http://localhost:5173. После первой сборки для работы над интерфейсом можно запускать `pnpm dev:web`. `pnpm build` собирает движок и приложение; результат — `web/dist`.

Для публикации в подкаталоге задайте базовый путь с завершающим `/`: `VITE_BASE_PATH=/armenian-belote-trainer-app/ pnpm build`. Путь используется также для manifest и service worker. Опубликованная демонстрация: https://mtigra.github.io/armenian-belote-trainer-app/ .

Обновление демонстрации из корня репозитория: после этой сборки выполните `python3 scripts/publish-pages.py` с авторизованным `gh`. Скрипт публикует только готовые файлы в ветку `gh-pages`; GitHub Pages использует корень этой ветки. Исходники и локальные данные пользователей в публикацию не входят.

В https://github.com/MTigra/armenian-belote-trainer-app/settings/pages настроена публикация **Deploy from a branch**, ветка **gh-pages**, каталог **/(root)**. Настройка подтверждена API GitHub, статус `built`; публичная ссылка отдаёт production-сборку по HTTPS.

## Что работает

- Приватные онлайн-столы по коду, четыре гостя, выбор свободного места в лобби, старт создателем, WebSocket, таймеры и возврат после reload. Каждый видит свою руку снизу; серверные места и счёт преобразуются для экрана без изменения команд/архива. При отсутствии более двух минут управляет бот; возвращение восстанавливает управление. Подробности в [сервере](../server/README.md).
- Онлайн продолжает работать в меню и чате. Завершённая запись с местом игрока, никами, таймером и собственным чатом сохраняется локально; активная офлайн-тренировка остаётся на месте.

- Офлайн-партия против трёх простых ботов: реальные восемь карт, торговля от 8, бой, обещанный капут, доступность контры/реконтры по движку, разрешённые карты, объявления и счёт до 301.
- Боты совершают только разрешённые действия. Пока они всегда пасуют в обычной торговле; пользователь делает заявку, иначе после четырёх пасов будет пересдача.
- Просмотр публичных объявлений и показанных комбинаций, без раскрытия непоказанных карт. Нажатие сразу играет допустимую карту. Рука помещается в один ряд без скролла, с увеличенными номиналами и мастями. Карты взятки располагаются со стороны сыгравшего игрока и повёрнуты к нему; та же раскладка используется при разборе. После четвёртой карты на короткое время видна выигранная взятка.
- Одна активная тренировка, сохранённая в IndexedDB после каждого действия. «Продолжить партию» в меню; новая тренировка требует подтверждения замены. Закрытие приложения восстанавливает сохранение. Открытый чат после перезагрузки остаётся на паузе.
- Завершённые матчи, полный архив исходных раздач и действий, собственный чат. Экспорт/импорт JSON, проверка версии и воспроизведение общим движком. Импортированная запись пересчитывается по действиям, а не доверяет счёту в файле.
- Просмотр по действиям; обычная перспектива игрока и отдельная полная раскладка завершённого матча.
- Боты приостанавливаются в меню и открытом чате. Отказ AI не мешает продолжить игру.
- PWA: после первого успешного онлайн-запуска production-сборка кешируется и открывается без сети. Для обновления версии нужно закрыть старые вкладки приложения. В режиме Vite dev service worker не используется.

## Что ещё не подключено

Публичное размещение Ktor, реальный AI-провайдер и Capacitor. Для локальной сетевой проверки используйте `pnpm dev:online`: Vite проксирует `/api` на :8080. Для GitHub Pages задайте `VITE_API_URL` при сборке или адрес HTTPS-сервера в «Настройки подключения». Без доступного сервера интерфейс показывает ошибку и позволяет продолжить офлайн.

Чат отправляет вопрос, четырёхзначный код и только `PlayerView`. Ktor сейчас возвращает 503 `TRAINER_UNAVAILABLE`; игра при этом продолжается. Момент фиксируется при отправке вопроса; в онлайне сообщения о прошлых состояниях помечаются. Фиктивных ответов и применения ходов модели нет.

В офлайне полный `GameState` остаётся в локальном контроллере и IndexedDB. В онлайне закрытые чужие руки остаются на сервере до завершения матча; клиент получает только свою проекцию. Стол, торговля и запрос тренеру используют информацию игрока. Гостевой токен хранится отдельно, не входит в архив/экспорт, в WebSocket передаётся первым сообщением.

## Проверки

После `pnpm engine:build`:

```sh
pnpm typecheck
pnpm test
pnpm --filter @blot/web build
pnpm --filter @blot/web exec playwright install chromium
# Ktor должен работать на :8080 (отдельный терминал: ./gradlew :server:run)
pnpm test:e2e
```

Vitest проверяет адаптер, IndexedDB, обмен архивами и изоляцию AI. Playwright на production-сборке разыгрывает настоящий матч, проверяет продолжение после reload, паузу ботов, отказ AI, историю, импорт/экспорт и запуск без сети. Отдельный сценарий проверяет касание карты, один ряд без скролла и расположение/поворот карт по местам при смене ориентации. Для имеющегося Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

В root CI добавлены проверки интерфейса. Исходный статический дизайн-макет сохранён в `docs/design-prototype/`; рабочее приложение — `web/`.
